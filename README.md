# 每天复核 100 笔支付，该选哪些？

这是一个支付风控实习练习项目。模拟团队在每天结束后，从当天交易中挑选有限数量的记录供人工复核。整天排序适用于事后调查；支付发生当下实时拦截需要另行设计。

## 运行

进入本目录，用 Python 3.10 或以上版本执行 `python run.py`。项目使用 Python 自带的 SQLite，无需安装依赖。默认生成固定随机种子的 72,000 笔模拟交易。前 40 天用于确定全局金额基准，后 20 天用于评估。结果写入 `demo_results`。

已有 CSV 时运行 `python run.py --csv transactions.csv`。必需列为 TRANSACTION_ID、CUSTOMER_ID、TX_DATETIME、TX_AMOUNT、TX_FRAUD。交易编号应唯一，金额为正数，标签为 0 或 1。时间使用 ISO 格式，无时区时按 UTC 处理。程序按实际有交易的日期划分前约三分之二和后约三分之一，输出到 csv_results。可以对照 [Fraud Detection Handbook 公开模拟数据](https://github.com/Fraud-Detection-Handbook/simulated-data-raw) 的字段，先将所需日期的交易整理为 CSV。

## 排序规则

- 大额优先。每天按交易金额降序取前 K 笔。
- 相对金额优先。用当前金额除以客户过去七天的平滑平均金额，再取前 K 笔。平滑时加入五笔按开发期全局均值计算的等效交易，减少历史太少时评分的波动。当天较早的交易可用于较晚交易的历史特征。欺诈标签仅用于事后评价。
- 平均数与中位数对照。mean 和 median 都使用当前金额除以客户过去七天的个人基准，分别采用普通平均数和中位数。没有历史时，两者都采用开发期全局平均金额。每天 100 个名额时，两种规则分别找到 164 笔和 171 笔；每天 50 个名额时分别找到 140 笔和 137 笔。上面的平滑平均数策略在表中叫 relative。

## 结果怎么读

打开 demo_results/comparison.csv。在每天 100 个名额下，两条规则在检验期各送审 2,000 笔。相对金额规则选中了 170 笔模拟欺诈，大额规则选中 147 笔。覆盖的欺诈金额占比分别为 87.52% 和 84.42%。这些指标假设事后标签完整。金额覆盖率表示已标记欺诈金额中进入队列的比例，实际挽回金额还取决于审核和处置效果。

生成器刻意加入了偏离个人消费习惯的欺诈情形，因此结果受模拟机制影响。把每天名额从 50 调到 200 时，比较不同策略的优势如何变化。再换一份独立数据检验结论。
